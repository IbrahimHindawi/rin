# Neovim support for rasm

Filetype detection, syntax highlighting, and LSP attachment for `.rasm` files.

## Install

Either install into your config:

```
python rasm/editors/nvim/install.py
```

| flag | effect |
| --- | --- |
| `--link` | symlink instead of copying, so edits in this repo apply without reinstalling |
| `--dest DIR` | install into a specific config directory |
| `--dry-run` | print what would happen, write nothing |
| `--uninstall` | remove the installed files |

The target defaults to Neovim's own config location: `%LOCALAPPDATA%\nvim` on
Windows (`~/AppData/Local/nvim`), `$XDG_CONFIG_HOME/nvim` or `~/.config/nvim`
elsewhere. `NVIM_APPNAME` is honoured.

Or use it straight from the repo, by putting this folder on the runtimepath
early in `init.lua` (before `filetype` detection runs, so `ftdetect` is read):

```lua
vim.opt.runtimepath:prepend("C:/devel/rin/rasm/editors/nvim")
vim.opt.runtimepath:append("C:/devel/rin/rasm/editors/nvim/after")
```

## Verify

Open any `.rasm` file and check:

```vim
:set filetype?     " filetype=rasm
:checkhealth lsp   " a rasm-lsp client, rooted at the project
```

## What gets installed

| file | purpose |
| --- | --- |
| `ftdetect/rasm.lua` | maps `*.rasm` to filetype `rasm` with `vim.filetype.add()` |
| `syntax/rasm.vim` | syntax highlighting |
| `ftplugin/rasm.lua` | `; %s` comments, 4-space indent, loads the LSP attachment |
| `after/ftplugin/rasm.lua` | starts and attaches `rasm-lsp` with `vim.lsp.start` |

## LSP entry point

The language server is `editors/lsp/rasm_lsp.py`, run as
`python -u rasm_lsp.py` over stdio. `after/ftplugin/rasm.lua` resolves it in
this order:

1. `vim.g.rasm_lsp_command`, if you set it
2. `$RASM_HOME/editors/lsp/rasm_lsp.py`
3. the repo path baked in by `install.py` at install time
4. `../lsp/rasm_lsp.py` next to this folder, when it is used from the repo
   through the runtimepath

If none of them exists it says so once and leaves highlighting working. The
project root is the nearest directory holding `.git`, else the file's own
directory.

To override it, set the command before the filetype loads:

```lua
vim.g.rasm_lsp_command = { "python", "-u", "C:/devel/rin/rasm/editors/lsp/rasm_lsp.py" }
```

If you manage servers with nvim-lspconfig / `vim.lsp.config` instead, skip
`after/ftplugin/rasm.lua` (don't install it, or set the command to something
that exits) and register it yourself:

```lua
vim.lsp.config("rasm_lsp", {
  cmd = { "python", "-u", "C:/devel/rin/rasm/editors/lsp/rasm_lsp.py" },
  filetypes = { "rasm" },
  root_markers = { ".git" },
})
vim.lsp.enable("rasm_lsp")
```

## Highlighting notes

- `;` starts a comment, as in MASM. `//` is not a comment in a `.rasm` file.
- **Mnemonics are coloured only as the first word of a statement**, after an
  optional `rep`/`lock` prefix. `out`, `in`, `test` and `loop` are
  mnemonics and also ordinary names (`out: *vec3`), so they stay plain
  anywhere else. A first word that is not a known mnemonic stays uncoloured,
  which makes typos visible. The list (1453 names: general purpose, x87,
  SSE to SSE4.2, AVX, AVX2, FMA, BMI, AVX-512) is generated by
  `editors/tools/gen_mnemonics.py` from asm-lsp's `x86_64.xml`; rerun it
  rather than editing the list.
- Registers, size words and mnemonics are lowercase only, as rasm's lexer
  reads them: `RAX` is a name, not a register.
- `#define NAME expr` is the only `#` line rasm accepts. Any other `#` line is
  shown as an error, and so is a `;` inside a `#define`, which C would read as
  part of the value.
- ALL_CAPS names are coloured as constants. That is a naming convention
  (`#define`s, Win32 constants, enum members), not something rasm knows.
- Type names are coloured in type positions: after `:`, `->`, `*`, `[N]`,
  `const` and `alias =`, and as the `T` of a typed path `[rbx].T.field`.
  `*Vtbl.Method` is coloured as a type and a method.
