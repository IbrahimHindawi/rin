# rasm_lsp

A language server for rasm. It runs the assembler on the text being edited and answers from what
the assembler found, so a hover shows the same offsets, sizes and values the program is built with.

    python -u rasm_lsp.py                 stdio, for an editor
    python rasm_lsp.py --check f.rasm     the diagnostics and a summary, without an editor
    python test_lsp.py                    talks to the server like an editor does, on 2.1 hello triangle

Python 3.10 or newer, standard library only. It needs a `rin` whose `rin asm` has `--index`
(rin after 2026-10-25), found as `$RASM_RIN`, then `$RIN_HOME/rin.exe`, then `rin` on `PATH`, then
the `build\rin.exe` of the rin checkout it lives in (`rin/rasm/editors/lsp`).

## What it does

| | |
|---|---|
| diagnostics | every error `rin asm` reports, on its line, 0.3 s after typing stops (errors in an imported file go to that file) |
| hover, instruction | summary, operand forms, ISA extension, a link to the reference |
| hover, register | what it is, and its Win64 role: argument 1..4, return value, volatile or callee-saved, what `calls.rasm` uses it for |
| hover, global or path | `bodies[1].pos.z`: the type, the offset from the global, the size, and the operand it assembles to |
| hover, `[rbx].T.f` | the same through a register |
| hover, struct / enum / alias | the layout with offsets and sizes; the values; what it resolves to (the Windows and D3D11 types included) |
| hover, `#define` | the text and its value |
| hover, a Windows function | its signature, and which register or stack slot each argument goes in, with the stack the call needs |
| hover, `Vtbl.Method` | the slot's offset: `call qword ptr [r10 + 24]` |
| hover, macro / proc / label | the body of each overload; the signature and labels; where a label is |
| definition | procs, labels, macros, globals, structs, enums, `#define`s, `import` paths |
| completion | mnemonics and macros at the start of a line; fields or members after `.`; registers, globals, constants, procs and the Windows API elsewhere |
| signature help | `invoke(f, ...)` and `vcall(obj, Vtbl.Method, ...)`: the register or stack slot of the argument being typed |
| document symbols | procs (their labels inside), macros, globals, structs, enums, `#define`s |

## How

Each change runs

    rin asm <file.rasm> --index <tmp.json> --stdin-path <file.rasm>

with the buffer on stdin. `--index` does everything a build does up to writing the `.s` (so every
check runs), then writes a JSON description of the program instead of assembling it. For 2.1 hello
triangle that is about 0.4 s and 2 MB, most of it the Windows and D3D11 binding.

## Data

`x86_64.json` holds the instruction summaries, operand forms and register notes. It is generated by
`gen_x86_docs.py` from [asm-lsp](https://github.com/bergercookie/asm-lsp)'s `docs_store`, whose
x86-64 tables come from the [Opcodes](https://github.com/Maratyszcza/Opcodes) package; both are
BSD-2-Clause.
